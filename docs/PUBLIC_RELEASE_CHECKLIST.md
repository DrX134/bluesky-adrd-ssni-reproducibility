# Public release checklist

Before making the repository public and citing it in the revised manuscript:

- [ ] Confirm the repository owner/name and final public URL.
- [x] Include the complete Stage-00 reviewed keyword rule artifact.
- [x] Include final 17-keyword and exclusion-term configuration files.
- [x] Use repository-relative paths in public notebooks.
- [x] Exclude raw Bluesky data from Git.
- [x] Link the public source dataset in the main README.
- [x] Include a run-order/pipeline map and expected checkpoints.
- [x] Include ratings-only human-validation data without post text.
- [ ] Choose an explicit open-source code license (e.g., MIT/BSD/Apache) with the coauthors/institution as appropriate.
- [ ] Create a GitHub release corresponding to the revision submission.
- [ ] Archive that release in Zenodo (recommended) and record the DOI.
- [ ] Add the GitHub URL (and Zenodo DOI if created) to the manuscript Data and Code Availability statement.
- [ ] Replace future-tense repository language in the response letter with the actual URL/DOI.
- [ ] Final spot-check that no raw post text, personal path, token, credential, or private file is committed.
